# M5Core2MusicRemote

M5Stack Core2 を [Music Assistant](https://www.music-assistant.io/)(miscpi 上で稼働)のタッチリモコンにする。HomePod(AirPlay)で再生中の YouTube Music をタッチ画面から操作する。物理○ボタン(A/B/C)は使わず、**操作は常にタッチのみ**。

[M5AtomMusicRemote](https://github.com/m-tkg/M5AtomMusicRemote)(ボタン1個版)の画面付き版。

## 画面と操作

```
                                   87%⚡  ← バッテリー残量(充電中は稲妻)/ OFFLINE 表示
┌──────┐ 曲名(日本語対応・3行まで)
│ アート │
│ 132px │ アーティスト名
└──────┘
[▓▓▓▓▓▓●░░░░░░░░░░]  ← 音量スライダー(タップ/ドラッグで設定)
 🔀    ◀◀      ▶/⏸      ▶▶   ← タップで操作(向きによらず常にこの位置)
```

- **曲名・アーティスト・アルバムアート**を 3 秒間隔でポーリング表示
- 曲名(efontJA 24px)・アーティスト名(16px)は各1行表示。**幅に収まらない場合はマーキー**(先頭3秒停止 → スクロール → 末尾で1.5秒停止 → 先頭に戻る)
- **右上にバッテリー残量(%)を表示**(小さめのフォント)。**50%未満は黄色、20%未満は赤**で警告表示。給電中は稲妻アイコンが追加で点灯する(`M5.Power`、30秒間隔で更新)。MA に届かない間は同じ位置に赤字で OFFLINE と表示
- **再生状態はテキストではなく中央アイコンで表現**: 再生中=⏸(タップで一時停止)、停止中=▶(タップで再生)
- **操作ボタンは画面のタップのみ**(🔀 シャッフル / ◀◀ 前の曲 / ▶⏸ 再生・一時停止 / ▶▶ 次の曲)。**音量スライダーの直下に固定表示**され、横向き・縦向きどちらでも同じ位置・同じ見た目
  - ◀◀ は**再生位置が3秒を超えていたら曲の先頭に戻り(seek)、3秒以内なら前の曲へ移動**する(スマホアプリの一般的な挙動と同じ)。再生位置はポーリング値(3秒間隔)をローカルで秒読み補間して判定
  - 🔀 は**キューのシャッフルをトグル**(`player_queues/shuffle`)。状態はアイコン色で表示(ON=シアン / OFF=ダークグレー)し、MA 側の状態ともポーリングで同期する
- **音量スライダー**: タップまたはドラッグでその位置の音量に設定。ドラッグ中は 400ms 間引きで送信し、離した時に確定値を送る
  - スライダーは全幅 = 0〜`MAX_VOLUME`(既定60)のスケール。右端いっぱいで上限値になる(誤操作での爆音防止)
  - **アート部分の短いタップでアート全画面表示をトグル**(拡大中は曲名・スライダー・操作ボタンを隠し、画面のどこかをタップで復帰)。曲中の任意位置へのシーク機能は、Music Assistant 側(YouTube Music プロバイダー)のシークが正しく動作しないため削除した
- タップ操作の通信中は画面中央にスピナー(回転アーク)を表示
- **IMU による向き自動補正(4方向)**: 本体を立てた向きに合わせて画面が自動回転する(0.5G しきい値 + 0.8秒の安定待ち。水平置きは現状維持)。レイアウト(アート・曲名・スライダー・操作ボタン)は向きに応じて再配置されるが、操作ボタンの役割(◀◀/▶⏸/▶▶)は常に固定
- IMU の軸は実測済み(MPU6886: 横・通常で +Y が上、+X が右端方向)。判定は `checkOrientation()`、rotation 対応は `kRotFor[]`

## 選曲ブラウザ

コンテンツ領域(アルバムアート/曲名のあたり)を**長押し(0.7秒)**すると選曲画面が開く。

- レベル0: 「♪ 再生キュー」「★ お気に入り曲」+ プレイリスト一覧
- レベル1: 曲一覧。タップで再生
  - キューの曲 → その曲へジャンプ(`player_queues/play_index`)
  - プレイリストの曲 → プレイリスト全体をキューに入れて**その曲から**再生(`play_media` + `start_item`)
  - お気に入りの曲 → 単曲再生
- スクロール: **スワイプ** or 物理ボタン(上下=ページ送り、**中央=戻る**)。ヘッダー左の「< 戻る」でも戻れる
- 曲一覧は 50 件ずつ追加ロード(最大200件)。スマートプレイリストは `allow_dynamic_tracks=true` で取得
- 大きな JSON レスポンスは PSRAM 上でパースする(`PsAllocator`)
- プレイリスト一覧は `music/browse` でプロバイダーを直接覗いて取得する(`music/playlists/library_items` は MA ライブラリに明示的に追加した分しか返らず、YT Music アプリ側で作っただけのプレイリストは出てこないため)

## セットアップ

1. `include/config.h.example` を `include/config.h` にコピーして Wi-Fi・MA トークン・player_id を設定
2. ビルド & 書き込み

```bash
pio run -t upload   # upload_speed は 115200 (それ以上だと書き込みが失敗する個体あり)
pio device monitor  # 115200bps
```

## 実装メモ

- M5Unified + ArduinoJson 7。`players/get` のレスポンスは数 KB あるため、ArduinoJson の filter で必要フィールドのみ抽出している
- 曲名の日本語表示は M5GFX 内蔵の efontJA を使用
- アルバムアートは MA の `imageproxy`(認証不要)から `size=256` の JPEG を取得し 0.375 倍で 96px に縮小描画。`size=96` 等は 400 が返るので不可(許可サイズは 256/512 など)
- ポーリング中でも音量ドラッグ中はサーバー値で上書きしない(操作優先)
- **全曲リピートを常時 ON に保つ**(`player_queues/repeat` = `all`。ポーリングで矯正し、dynamic queue で失敗するケースに備えて 1 回のみ試行)
- MA API: `POST http://<MA_HOST>:8095/api`(Bearer トークン認証)。コマンド仕様は `http://<MA_HOST>:8095/api-docs`
